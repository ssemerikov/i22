Iнструкцiя: Деплой app2express на Render.com та альтернатива Fly.io


Цей документ описує, як розгорнути проєкт app2express (Express 5, JSON-файли, аутентифікація) на безкоштовному хостингу.


1. Підготовка проєкту перед деплоєм

Спочатку потрібно внести дві невеликі зміни у код, щоб проєкт працював на хмарному сервері.

Відкрийте файл server.js і знайдіть рядок:

const port = 3000;

Замініть його на:

const port = process.env.PORT || 3000;

Це дозволить хостингу призначити свій порт через змінну середовища PORT.

Далі відкрийте package.json і додайте блок engines, якщо його ще немає. Весь файл має виглядати приблизно так:

{
  "name": "app2",
  "version": "1.0.0",
  "description": "2 спроба створення веб-додатку із Node.js",
  "main": "server.js",
  "scripts": {
    "start": "node server.js"
  },
  "engines": {
    "node": "20.x"
  },
  "author": "Певний студент",
  "dependencies": {
    "express": "^5.2.1"
  }
}

Збережіть зміни і зробіть коміт у Git:

git add server.js package.json
git commit -m "Підготовка до деплою: порт з env та engines"

Завантажте зміни на GitHub (render.com працює тільки з GitHub-репозиторіями).


2. Реєстрація на Render.com

Перейдіть за адресою https://render.com і натисніть Sign Up.

Зареєструйтеся через обліковий запис GitHub (найпростіший спосіб).


3. Створення Web Service на Render

У панелі Render натисніть кнопку New і оберіть Web Service.

Підключіть свій GitHub-репозиторій. Render покаже список репозиторіїв, до яких ви надали доступ. Знайдіть той, що містить папку app2express.

Заповніть форму створення сервісу:

Name — назва вашого сервісу, наприклад app2express-api.

Region — оберіть найближчий регіон (Frankfurt — найближчий для України).

Branch — main (або інша гілка, з якої ви хочете деплоїти).

Runtime — Node.

Build Command — npm install

Start Command — node server.js
n
У полі Root Directory вкажіть app2express, якщо ваш репозиторій має кореневу папку з такою назвою. Якщо файли server.js і package.json лежать у корені репозиторія, залиште поле порожнім.

Натисніть Create Web Service.


4. Налаштування змінних середовища (Environment Variables)

Після створення сервісу перейдіть на вкладку Environment у панелі Render.

Додайте змінну:

Key: NODE_ENV
Value: production

Натисніть Save Changes.

На вкладці Settings переконайтеся, що Auto-Deploy обрано Yes (за замовчуванням так).


5. Перевірка деплою

Render почне збірку. Це займе кілька хвилин. У розділі Logs ви побачите процес встановлення залежностей і запуск сервера.

Після успішного деплою Render надасть URL типу:

https://app2express-api.onrender.com

Відкрийте цей URL у браузері. Ви маєте побачити стартову сторінку бібліотеки (index.html із папки public).

Перевірте роботу API за допомогою curl:

curl https://app2express-api.onrender.com/api/health

Відповідь має бути JSON із полем success: true.

Перевірте список книг:

curl https://app2express-api.onrender.com/api/books


6. Обмеження безкоштовного тарифу Render

Безкоштовний Web Service на Render має такі обмеження:

RAM — 512 МБ. Для Express-сервера з JSON-файлами цього достатньо.

CPU — спільний (shared), швидкість обмежена.

Spin down — сервер зупиняється після 15 хвилин бездіяльності. Наступний запит буде оброблено через кілька секунд (cold start), поки сервер прокидається.

Бази даних — безкоштовна PostgreSQL база даних видаляється через 30 днів. Для постійного зберігання використовуйте MongoDB Atlas (див. окрему інструкцію mongodb-setup-and-app4.txt).

Немає підтримки кастомних доменів на безкоштовному тарифі.


7. Альтернатива: Fly.io

Якщо cold starts на Render вас не влаштовують, Fly.io — хороша безкоштовна альтернатива. ВМ на Fly не зупиняються через бездіяльність.

7.1. Реєстрація

Перейдіть на https://fly.io і зареєструйтеся. Потрібна банківська картка для верифікації (кошти не знімаються, якщо ви залишаєтесь у межах безкоштовного ліміту).

7.2. Встановлення flyctl

У Linux/macOS:

curl -L https://fly.io/install.sh | sh

Після встановлення додайте flyctl у PATH або перезапустіть термінал.

Увійдіть у обліковий запис:

fly auth login

7.3. Запуск проєкту

Перейдіть у папку проєкту (app2express):

cd app2express

Запустіть ініціалізацію:

fly launch

Fly задасть кілька питань:

App Name — унікальна назва (наприклад, app2express-api).

Region — оберіть найближчий (fra — Frankfurt).

PostgreSQL — відповідайте No (ми використовуємо JSON-файли або MongoDB).

Redis — відповідайте No.

Fly автоматично створить Dockerfile та файл fly.toml на основі вашого package.json.

7.4. Деплой

Запустіть:

fly deploy

Після завершення ви отримаєте URL типу:

https://app2express-api.fly.dev

7.5. Переваги Fly.io над Render

Always-on — ВМ не зупиняються після бездіяльності.

3 shared-CPU-1x машини безкоштовно.

3 GB persistent volumes для збереження файлів.

Глобальні регіони для мінімальної затримки.

7.6. Обмеження Fly.io

Потрібна картка для реєстрації.

Легко перевищити безкоштовні ліміти (стежте за лімітами у панелі).

Бази даних не є повністю керованими — зазвичай підключають зовнішні сервіси (MongoDB Atlas, Neon, Supabase).


Підсумок

Render.com — найпростіший варіант для початку, але має cold starts.

Fly.io — кращий вибір, якщо вам потрібен always-on сервер і ви готові додати картку для верифікації.
