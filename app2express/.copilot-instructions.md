# Copilot Instructions - app1 Books Management API

Purpose: Help future Copilot sessions understand and work effectively with this Node.js books management API.

## Build, test, and lint commands

**Start the server:**
```bash
npm start
# or directly:
node server.js
```
Server runs on `http://localhost:3000` by default.

**Test the API:**
- GET books: `curl http://localhost:3000/api/books`
- Health check: `curl http://localhost:3000/api/health`
- Add book: `curl -X POST -H "Content-Type: application/json" -d '{"title":"Title","author":"Author"}' http://localhost:3000/api/books`
- Delete book: `curl -X DELETE http://localhost:3000/api/books/1`

**No test suite is configured.** If adding tests, prefer adding npm scripts (e.g., `npm test`) to package.json.

## High-level architecture

This is a simple books management system with:
- **Backend:** Node.js HTTP server (`server.js`) with built-in routing (no framework)
- **Frontend:** Single-page app in `public/` folder (HTML/CSS/JS)
- **Data persistence:** In-memory JSON array (loaded from `books.json` on startup; not persisted to disk)

### Key files:
- `server.js` – HTTP server with CRUD endpoints for books
- `public/index.html` – Book library UI
- `public/client.js` – Client-side fetch API calls and DOM manipulation
- `public/styles.css` – Basic styling
- `books.json` – Initial data (JSON array with id, title, author)

### API endpoints:
| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/books` | GET | Fetch all books |
| `/api/books` | POST | Add new book (auto-assigns id) |
| `/api/books/:id` | DELETE | Remove book by id |
| `/api/health` | GET | Server health status |

CORS is enabled with wildcard origin. OPTIONS requests are handled for preflight.

## Key conventions and repository specifics

### File structure
- **public/** – all frontend assets (index.html, client.js, styles.css) must be in this directory; server.js serves from here
- **books.json** – must be in the same directory as server.js; structure: `[{id, title, author}, ...]`

### Server behavior
- Reads `books.json` synchronously on startup via `fs.readFileSync()` — changes to the file after server start won't be picked up
- Books are stored in memory only — modifications are lost on server restart (by design)
- Route matching is case-sensitive (`/api/books` not `/API/Books`)
- All responses are JSON with `Content-Type: application/json`

### Client-side patterns
- Uses async/await with fetch API (no external HTTP library)
- `loadBooks()` is called on DOMContentLoaded — the app auto-loads on page load
- Status messages auto-clear after 10 seconds
- Delete button for each book uses inline `onclick` handlers with book.id

### Localization
All UI strings are in **Ukrainian** (uk):
- HTML lang attribute: `lang="uk"`
- Comments and console messages in Ukrainian
- Input placeholders and labels in Ukrainian
- Keep this convention when adding new UI strings

### Common gotchas
- `books.json` must be valid JSON — invalid JSON will crash the server at startup
- Server only binds to `localhost:3000` by default; modify `port` and `.listen()` if changing
- No input validation on POST body — malformed JSON in request body will crash the handler
- Delete by id is simple array filter — behavior is undefined if book id is not unique (unlikely with auto-increment pattern)

## Development workflow

When modifying the server:
1. Start the server: `npm start`
2. Test endpoints with curl or browser fetch
3. Restart server to reload `books.json` changes (data in memory persists until restart)
4. Check console output for request logging (every request logs `method, pathname`)

When modifying the frontend:
1. Make changes in `public/` files
2. Refresh browser (no build step required)
3. Check browser DevTools console for any client-side errors
